# Документация Hotel Booking Service

Документация описывает текущую реализацию сервиса по исходному коду проекта.
Компонентная модель показывает обязанности модулей и взаимодействие между ними;
структурная модель — организацию кода, сущности, поля и связи данных.
Диаграммы записаны в Mermaid и отображаются в Markdown-просмотрщиках с его поддержкой.

## Назначение и границы

Сервис предоставляет HTTP API для создания, удаления и просмотра гостиничных номеров
и броней. Данные сохраняются в PostgreSQL. Клиентом может быть внешнее приложение
или HTTP-инструмент, например `curl`; собственного пользовательского интерфейса нет.

Реализация представляет собой монолит: компоненты приложения работают в одном
Django-проекте и используют общую базу данных. Контейнеры `web` и `db` разделяют
приложение и хранилище, но не образуют набор бизнес-микросервисов.

Авторизация API, пользователи бронирований, платежи, отдельная сущность гостиницы,
изменение существующих записей и пагинация не реализованы. Цена хранится у номера;
стоимость проживания и валюта в модели не определены.

Инструкции по запуску через Docker Compose, настройке WSL и локальной разработке
находятся в [основном README](../README.md). Источники архитектуры:
[приложение hotel](../src/hotel/), [конфигурация](../src/config/),
[Compose](../compose.yaml) и [тесты](../tests/).

## Поддержание документации

При изменении маршрутов и сериализаторов обновляйте контракт API; при изменении
сервисов — компонентную модель и сценарии; при изменении моделей и миграций —
структурную модель. Описания отражают реализованное поведение, а не план развития.

## UML-исходники

Каталог [`docs/uml`](uml/) содержит файлы `.puml`, которые можно открыть в PlantUML,
VS Code с расширением PlantUML или на совместимом сервере рендеринга. Диаграммы
дублируют основные модели из Markdown, но остаются редактируемыми исходниками UML.
